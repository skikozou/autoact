# 目的と背景

## 何を作ったか

任意テキスト (漢字/カナ/ひらがな/英数字/記号) を Gboard の実キー操作に落として入力するパッケージ。

```
python3 type_text.py "価格 $100 と ¥1,500"
  → 実機の Gboard が か→カ→ク の順にフリックされ、
    変換候補「価格」がタップされ、
    英字モードに切り替わり "$100 " が打たれ、
    ひら戻って と、
    英字戻って " ¥1,500" が打たれる
```

## なぜ `setText` (a11y ACTION_SET_TEXT) じゃないか

`setText` は EditText に直接文字列を書き込むだけで、IME を通さない。すると:

1. **IME を経由する入力そのものを再現できない** — スクリーンリーダやログ収集、ユーザ観察の対象にならない
2. **見た目のフリックが起きない** — 動画キャプチャや操作トレースで実際のキー入力として現れない
3. **候補学習が走らない** — Gboard の変換履歴に載らない、次回変換で「価格」が上位に来ない
4. **一部 EditText は setText を拒否する** — WebView 内の input、Compose の TextField、独自 IME 実装

対して flick 経由は:
- IME を通した本物の入力なので、上記が全部成立する
- 代償として遅い (10cps 程度) — が、UI テストや観察用途では正当

## 位置づけ

`autoact` の座標打鍵 + a11y click を組み合わせて **Gboard のフリック入力全体を Python から発火する薄いラッパ**。

- 座標データは実機 probe で確定 (`probe_*.py` 参照)
- Gboard の癖 (multi-tap, mode切替, canvas 描画) はパッケージ内部で吸収
- 呼び出し側は `type_text.type_arbitrary(text, cfg)` を叩くだけ
